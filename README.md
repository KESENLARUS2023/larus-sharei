# larus-sharei

ラルスに関わる帯同審判・帯同MC・その他従事者の謝礼に係る支出を管理するためのものです。

KESEN LARUS BASKETBALL CLUB の「交通費等及び謝礼金支給規程」第5条（帯同審判謝礼金）・第6条（コミッショナー謝礼金）等に基づき、対象者への謝礼金を取りまとめるWebアプリです（交通費取りまとめアプリとは別管理）。データはFirebase（Firestore + Authentication）に保存され、共有の合言葉でログインした端末同士でリアルタイムに同期されます（PC・スマホなど複数端末から同じデータを見られます）。ログイン用のアカウントは交通費取りまとめアプリと共通のため、同じ合言葉でログインできます。

## 使い方

0. `index.html` をブラウザで開く（GitHub PagesのURL、または `python3 -m http.server` 等で配信）。ログイン画面が表示されるので、共有の合言葉（交通費アプリと同じもの）を入力します。**`?key=合言葉` を付けたURL**（例: `https://.../?key=xxxxxx`）を開いた場合は、この入力なしで自動的にログインされます。LINEなどでリンクを共有する際はこの形式のURLを使うと、ブラウザの種類やアプリ内ブラウザかどうかに関係なく毎回確実にログインできます
1. **入力タブ**: 日付・区分（帯同審判／コミッショナー／その他）を選びます。区分・試合種別・活動場所などはボタンを押して選びます。日付の初期値は端末の今日の日付です
   - **帯同審判**: 試合種別（練習試合／公式戦）を選びます。練習試合の場合は活動場所（気仙管内／気仙管外）・拘束時間（半日／1日）で支給額が決まります。公式戦の場合は1試合2,500円で、担当した試合数（最大3試合）を選ぶとその分がまとめて計算されます
   - **コミッショナー**: 活動場所（気仙管内／気仙管外）を選び、担当した試合数（最大3試合）を選ぶと支給額が自動計算されます。気仙管内は謝礼1,000円×試合数、気仙管外は謝礼1,000円×試合数に加えて気仙管外の支給（下記）が上乗せされます
   - **気仙管外の支給方法**（帯同審判の練習試合・コミッショナーで活動場所が気仙管外の場合に表示）: 「交通費（1,000円）」か「弁当」を選べます。交通費を選ぶと1,000円（1日1回のみ・試合数に関わらず定額）が現金支給額に加算され、弁当を選ぶとその分は現金では加算されず、精算書には「弁当（気仙管外）」と印字されます（例: コミッショナーが気仙管外で2試合担当し交通費を選んだ場合は謝礼2,000円＋交通費1,000円＝合計3,000円。弁当を選んだ場合は謝礼2,000円のみ）
   - **その他**: 上記に当てはまらない従事者への支払い用です。内容（自由記述）と支給額を直接入力します
   - 対象者は、よく依頼する人のボタンを押して選ぶか、「その他（自由入力）」を選んでその都度お名前を入力できます。**複数人を選ぶと、同じ内容で人数分をまとめて登録**できます（同じ日に複数人へ依頼した場合など）
   - 大会開催地は、過去に入力した開催地が候補として表示されます
   - 大会開催地（任意）を入力しておくと、精算書にそのまま印字されます
   - 「登録する」を押すと記録されます
2. **一覧タブ**: 登録済みの記録をスプレッドシート風の表で確認できます（スマホ・タブレットでは1件1枚のカード表示）。月や氏名で絞り込み可能です。
   - 支給額は一覧で直接修正できます。変更前後の金額を確認してから保存し、空欄・マイナス・小数は受け付けません
   - 各行の「…」から**編集**（入力タブに内容を読み込んで、日付・氏名・区分なども含めて修正）と**削除**ができます
   - 「この一覧をExcel出力」で、表示中（絞り込み後）の記録だけをExcelファイルで出力できます
   - 各行の「精算書」ボタンを押すと、その記録1件分の精算書（審判謝礼精算書／コミッショナー謝礼精算書／謝礼金精算書）がブラウザの印刷ダイアログに表示されます。印刷先を「PDFに保存」にすればPDFとして保存・共有できます。「精算書」の隣の「封筒」ボタンを押すと、その記録の日付・対象者の封筒を印刷できます（下記「封筒印刷」参照）
   - 精算書には、登録時点の明細と記録の支給額が印字されます。一覧で支給額を修正した記録は、明細が支給額1行にまとまります（後から規程の金額を変えても、過去の精算書の金額は変わりません）
3. **ダッシュボードタブ**: 対象年度（4月始まり〜翌年3月）を選ぶと、年間合計費用・支払件数・活動月平均費用・支払額トップの対象者を一目で確認できます。月別の費用推移、区分別（帯同審判の練習試合／公式戦・コミッショナー・その他）の費用内訳、対象者別の支払額・件数をグラフと表の両方で表示します
4. **対象者の登録・削除**: 入力タブ下部の「よく依頼する対象者の登録・削除」から、頻繁に依頼する人の名前をあらかじめ登録・削除できます。ここに登録していない人への謝礼は「その他（自由入力）」でその都度入力してください（過去の記録に影響はありません）
5. **精算書用の連絡先・住所の設定**: 入力タブ下部の「精算書用の連絡先・住所を設定」から、よく依頼する対象者ごとに精算書へ載せる住所・電話番号をあらかじめ登録できます（Firestoreに保存され、全端末で共有されます）

## 封筒印刷（現金手渡し用）

一覧タブの各行にある「封筒」ボタン（「精算書」ボタンの隣）を押すと、その記録の対象者・日付の長形3号封筒（120×235mm）の宛名面をブラウザの印刷ダイアログに表示します。

- 封筒には対象者名・日付（「令和8年8月15日」の形式）・金額が印字されます
- 同じ対象者に同じ日付の記録が複数ある場合（例: 同日に帯同審判とコミッショナーを担当）は、その日の合計金額を1枚の封筒にまとめて印字します
- 印刷ダイアログで用紙サイズを「長形3号」（対応がない場合は「ユーザー定義」で120×235mm）に設定し、プリンタの封筒トレイ等にセットして印刷してください
- 宛名・金額を印刷する仕様のため、印刷後は手渡しの直前まで人目につかない場所で保管することをおすすめします

## バックアップ（Excel出力・取込）

一覧タブの「データのExcel出力・バックアップ復元」から、以下ができます。

- **Excel出力**: 全期間・全対象者の記録を、日付・氏名・区分・試合種別・活動場所・拘束時間・試合数・管外支給・内容・支給額・大会開催地・備考の列を持つ`.xlsx`ファイルとしてダウンロードします。改修や機種変更の前など、定期的に保存しておくことをおすすめします
- **取込**: 出力したExcelファイル（.xlsx）をそのまま読み込むと、記録を復元できます。CSV（UTF-8、またはExcelで保存したShift_JIS）にも対応しています。日付・氏名・区分・支給額などが同じ内容の記録は重複登録されません

## データの保存先とログインについて

このアプリはFirebase（Firestore + Authentication）を使ってデータを保存しています。交通費取りまとめアプリ（別リポジトリ）と同じFirebaseプロジェクト・同じログインアカウントを使っていますが、データ領域（コレクション）は別（`sharei_records` / `sharei_meta`）です。

- **アクセス制限**: 交通費アプリと共通のFirebase Authenticationアカウントでログインします。合言葉（パスワード）を知らない人はデータを閲覧・編集できません
- Firestoreのセキュリティルールは交通費アプリ側で設定済みの「ログイン済みユーザーのみ読み書き可（`allow read, write: if request.auth != null;`）」がそのままこのアプリのデータ領域にも適用されるため、このアプリのために追加のルール設定は不要です
- 合言葉を変更したい場合は、Firebaseコンソール → Authentication → Users タブから、共有アカウントのパスワードをリセットしてください（交通費アプリ側と共通のパスワードです）
- **接続にはインターネット接続が必要です**

### 合言葉入りURL（LINE共有用）

`https://（GitHub PagesのURL）/?key=（合言葉）` の形式でURLを作ると、開いた瞬間に自動でログインされます。交通費アプリと同じ仕組みです。詳しくは交通費アプリのREADMEをご参照ください。

### firebase-bundle.js について

`firebase-bundle.js` は、Firebase JS SDKと `firebase-entry.js`（初期化コード）を [esbuild](https://esbuild.github.io/) でひとつのファイルにまとめたものです。外部CDNに依存せず動作します。`firebaseConfig` を変更した場合など、再ビルドが必要なときは以下を実行してください。

```
npm install firebase esbuild
npx esbuild firebase-entry.js --bundle --format=iife --platform=browser --minify --outfile=firebase-bundle.js
```

## キャッシュ対策（アセットのバージョニング）

`.github/workflows/version-assets.yml` により、`main` ブランチへのpushのたびにGitHub Actionsが自動的に `index.html` 内の `app.js` / `style.css` / `firebase-bundle.js` の読み込みURLへ `?v=YYYYMMDDHHMMSS`（UTC・push時刻）を付与するコミットを追加します。これにより、コード更新後にブラウザの古いキャッシュが表示され続ける問題を軽減します。GitHub Pagesの設定変更は不要です（Deploy from a branch のまま動作します）。

`logo.png`（KESEN LARUSロゴ・背景透過）は精算書の出力に使用しています。差し替える場合は同じファイル名で置き換えてください。
